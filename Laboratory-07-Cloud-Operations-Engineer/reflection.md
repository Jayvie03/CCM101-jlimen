# Laboratory 07 – Reflection

This laboratory activity helped me understand the importance of monitoring both the host server and the containers running on it. First, it is important to check the host server's resources even when containers are running perfectly because the server still provides the CPU, memory, and storage needed by the containers. A container may appear to be working normally, but limited host resources can eventually affect its performance. Checking the host resources helps identify possible problems before they become serious.

The `docker logs` command is also useful when troubleshooting a web application. If a user cannot log into an application, I can use `docker logs` to look for errors, failed requests, or other information generated by the application. The logs can help identify what happened when the user experienced the problem. In this laboratory, I used the logs to see successful requests with status code `200` and the request that produced a `404` error.

Monitoring logs and monitoring metrics provide different types of information. Logs show events, requests, errors, and other activities that happen inside the application. Metrics, on the other hand, show numerical information about resource usage. Using `docker stats`, I was able to monitor the container's CPU usage, memory usage, and network activity.

Large enterprise companies need a more organized way to monitor thousands of containers. Tools such as Prometheus and Grafana can help collect, monitor, and visualize performance information from many systems and containers.

Finally, this laboratory improved my ability to troubleshoot Linux environments. I became more comfortable using commands such as `free -h`, `df -h`, `top`, `docker logs`, and `docker stats`. I also learned that troubleshooting involves checking different sources of information instead of relying on only one command.
