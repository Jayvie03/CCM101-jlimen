# Mission Reflection

During this laboratory activity, I learned more about the different components that make up cloud infrastructure and how they work together. I think **compute resources** are one of the most important components because they provide the processing power needed to run applications, services, and different tasks. Without enough computing resources, applications may not work properly or may become slow. While using KillerCoda, I was able to check the CPU model and number of CPU cores, which helped me understand the actual computing resources available in a Linux cloud environment.

I also learned how **Linux supports cloud computing** by providing an operating system that manages server resources and allows applications and services to run. Using the Linux terminal, I was able to check the CPU, memory, storage, networking, and other information about the server. This helped me understand how Linux commands can be useful when working with cloud servers.

I learned that **technical documentation is important before deploying infrastructure** because it keeps information about the system organized and helps engineers understand the available resources. Good documentation can also make it easier to troubleshoot problems and maintain the infrastructure in the future. During this activity, I learned new skills such as using Linux commands like `lscpu`, `free -h`, `lsblk`, `df -h`, `hostname`, and `hostname -I` to investigate a server. I also learned how to identify cloud infrastructure components, compare services from AWS, Microsoft Azure, and Google Cloud, and create a simple cloud infrastructure diagram.

After completing this mission, my **GitHub portfolio** became more organized and complete because I added another laboratory activity with an infrastructure report, cloud component documentation, a cloud provider comparison, screenshots, and a cloud architecture diagram. This helped me see how I can use GitHub to document my learning and show my progress in cloud computing.
